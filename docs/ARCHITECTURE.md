# 设计与关键决定

v0.2.0 新增 website/ 独立网页版，部署到用户指定的 Cloudflare Workers 与自定义域名。该版本在浏览器执行音乐核心和导出，仅由 Worker 转发 AI 请求；详情见 WEB_DEPLOYMENT.md。下述 Python 本机版设计继续保留，两种实现通过参考谱测试检查音符、指法与 MIDI 一致性。

## 数据流

图片 → 浏览器裁剪 → Python 规范化 PNG → 用户指定的视觉接口 → 严格简谱文本 → 人工校对 → 音高序列 → 动态规划指法 → 四线谱、MIDI、MusicXML。

## 为什么选择联网 AI

用户明确要求只用联网 AI，提高对简谱音点和节奏线的理解能力，因此不包含普通文字 OCR、本地识别模型或模型下载。Pillow 仅用于图片解码、方向校正与大小限制。

## 本机工作台

Python 标准库 ThreadingHTTPServer 配合无框架 HTML/CSS/JS，降低安装和二次开发成本。Windows 可用 PyInstaller 打包为一个 exe；打开系统浏览器作为 GUI，不要求 Electron、Node.js 或额外桌面运行时。

不依赖 CDN、字体服务或在线脚本。只有点击识谱时联网。浏览器用 Web Audio 合成试听，Blob 下载导出文件。

## 音乐表示

时值采用 Fraction，避免连续附点、短音符出现浮点误差。1=C 对应 C4，依照 1= 与大调级数计算实际 MIDI 音高；升降号只作用当前音。用户明确选择整体移八度才改变实际音高。

字符串坐标由上至下为 A/E/C/G，对应 MusicXML 技术指法的第 1–4 弦。普通定弦为 A4/E4/C4/G4，低 G 为 A4/E4/C4/G3。

每个音先列出可用弦位与品位，再通过动态规划最小化低把位成本、换弦与移动距离。休止和超出音域的音会重置手位连续性。当前仅单音，无和弦同弦冲突。

MIDI 与 MusicXML 使用每四分音符 960 tick，可精确表示最短 /32 附点音。SVG 简谱与 TAB 同列对齐，每音明确标出拍数；不声称具有专业刻谱软件的完整排版能力。

## 输入与访问边界

服务监听 loopback、校验 Host、Origin 与随机会话 token，静态文件走固定白名单；不暴露任意磁盘读取。图片最多 12 MB / 2400 万像素；HTTP 正文最多 18 MB；音符数最多 4096。

不记录用户图片、密钥、接口内容。所有导出重新从当前冻结的输入计算；修改谱面控件会使已有预览失效，必须重新生成，防止导出旧谱。工程保存、打开均由用户点击触发。

## 后续方向

真实谱图评测集、逐音可视化编辑、三连音与连音线、多声部选择、可调指法、分页 PDF。新增功能前，先补充能证明实际音乐语义的回归用例，避免只对渲染结果做镜像测试。

## 网页版 v0.4.0 增量

网页音乐核心增加 Gb 调号与 ~ 同音延音连接，保持跨小节片段及小节号，限制延音两端为相同音高且使用相同弦位。SVG 的括号品位表示延续，MIDI／试听只触发一次，MusicXML 输出 tie／tied 起止。异音连奏、反复仍不直接解析；《童话》示例的反复在数据层按用户确认路线展开，原谱小节号在工程和 PDF 中可追踪。Python 本机版尚未迁移 ~ 或 Gb，Windows 便携成品仍为 0.1.0。
